What has been verified

Inspect the recorded workflow: the source, the person’s decision, the saved files and the later recovery sequence

7 OCTOBER 2026 / HOSTED APP

The owned case recorded review of working version 2, the content decision, and separate JSON and PDF approvals and saves. Downloaded files matched the recorded outputs: JSON 9,531 bytes and PDF 50,137 bytes

Source inspection, review decisions and file approvals are separate steps. The video does not show external recipient delivery
LOCAL / BROADER WORKFLOW

Selected-claim checks, source-bound findings, human correction, exact-version decision binding and explicit unconfirmed outcomes have been implemented and locally tested in synthetic cases. This broader verification is separate from the hosted video

9 OCTOBER 2026 / DESIGNATED PDF

A controlled mismatch in the approved PDF’s file-format metadata caused download refusal and an incident record. After metadata restoration, the PDF was separately quarantined and released by an authorised operator. The recovered download matched the approved PDF byte for byte; the same job’s JSON stayed available and unchanged

This later QA sequence reused the approved PDF; it is separate from the 7 October video. File release left the incident open
10 OCTOBER 2026 / LOCAL REPLAY CONNECTION

Selected-policy application has been connected to actual replay judgment and the result record in the local implementation, with targeted backend and screen checks passed

Hosted rollout and acceptance of this new connection remain separate. Replay preserves the original record and does not activate a production policy

The cases use owned, noncustomer test material. These results do not establish financial-institution production outcomes, prevention of a named breach, recipient delivery, or MAS certification
